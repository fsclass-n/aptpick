# 01. aptpick 프로젝트 초기 구축 (2026-11-26)

## 배경
- 저장소(`fsclass-n/aptpick`)에는 `readme.md` 한 줄만 존재 → 동일 팀의 parkpick·recipepick 프로젝트 규칙(FastAPI + React/Vite, 루트 단일 `.env`, Render Blueprint·Netlify Git 연동, EC2 SSH 배포)을 기준으로 신규 구축
- 기존 도메인(`aptpick.netlify.app`, `aptpick.onrender.com`, `aptpick-api.onrender.com`, `aptpick.duckdns.org`)은 설정 파일에 그대로 반영, 플랫폼 연결은 아직 되어 있지 않음(모두 미응답 확인)

## 검증
- 백엔드 pytest 19건, AI pytest 4건 통과
- 프런트엔드 빌드: 실제 API 모드 / Mock 모드 모두 성공 (Mock 청크는 Netlify 빌드에만 포함)
- 로컬 통합 실행(uvicorn + vite) 후 Playwright 로 메인·검색·지도·시장·상세·예측·추천·로그인·관리자·모바일 화면 확인, 콘솔 오류 수정
- Netlify Mock 빌드에서 로그인 → 추천 → 관심 등록 → 가격 알림 → 관심 매물 흐름 확인

## 발견·수정한 문제
- 이상치 탐지 정밀도 13% → 최소 편차 15% 조건 추가로 65% (평가 스크립트로 발견)
- 80% 예측 구간 실제 포함률 67.6% → 등각 배율 보정(×1.5)
- Leaflet StrictMode 이중 마운트 시 `_leaflet_pos` 오류 → 제거 후 호출 가드
- 로그인 후 `next` 경로 대신 홈으로 이동 → GuestOnly 리다이렉트 수정

## 남은 작업 (외부 설정 필요)
- Render Blueprint 연결 및 `sync: false` 환경 변수(TiDB·API 키) 입력, Netlify 사이트 연결
- AWS EC2 부트스트랩 및 GitHub Secrets(`EC2_HOST`·`EC2_USER`·`EC2_SSH_KEY`) 등록
- `DATA_GO_KR_API_KEY` 발급 후 실거래 수집 → 샘플 삭제 → AI 재평가, OAuth Client 등록, Gemini 키 등록
- 최종 발표자료(PPTX)·PDF 산출물은 실데이터 전환 후 작성 예정

## 배포 수정 (2026-11-26)
- Render Docker 서비스가 리포 루트 컨텍스트에서 `Dockerfile` 을 찾지 못해 빌드 실패(`open Dockerfile: no such file or directory`)
  - 조치: 리포 루트에 백엔드 빌드용 `Dockerfile` 추가(내용은 `backend/Dockerfile` 과 동일, `COPY backend/…` 경로만 조정)
  - rootDir=backend 로 설정된 서비스는 기존 `backend/Dockerfile` 을 그대로 사용하므로 양쪽 설정 모두 동작
  - `.dockerignore` 3종 추가(루트·backend·frontend): 컨텍스트에서 node_modules/dist/data/docs 등 제외
  - Render 대시보드에서 Root Directory 를 `backend` 로 지정하면 루트 Dockerfile 없이도 동일 결과
- 주의: 프런트엔드를 Render Docker 서비스로 만들면 `VITE_*` 환경 변수가 Docker build ARG 로 전달되지 않아 API 주소가 잘못 박힘 → 프런트는 `static` 런타임 유지
