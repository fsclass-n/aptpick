# 데이터베이스 설계서

> 작성: 홍기흥 · DBMS: TiDB Cloud (MySQL 호환) · **Database: `aptpick`** · ORM: SQLAlchemy 2.0 (`backend/app/models/__init__.py`)
> 가격 단위 만원 · 면적 전용 ㎡ · 시각 UTC · `source` 로 실데이터(`molit`)와 가상 샘플(`sample`) 구분

## 1. ERD 요약

```
regions 1─N apartment_complexes 1─N apartments 1─N properties 1─N property_images
                     │                    │
                     ├─N transaction_history (apartment_id SET NULL)
                     ├─N rental_history
regions 1─N regional_statistics (region_code, period UNIQUE)
users 1─1 user_preferences · 1─1 admin_users · 1─N favorite_properties · 1─N price_alerts · 1─N notifications · 1─N recommendation_history
apartments 1─N price_predictions      model_versions (kind·version)
infrastructure (region_code, 좌표)     analysis_reports · data_sources · data_collection_logs · audit_logs · search_logs · inquiries
```

## 3. 설계 원칙 적용
- **중복 방지**: `source_key = sha1(source|aptSeq|면적|층|금액|월세|계약일)` UNIQUE + 수집 시 사전 조회
- **정규화**: 거래일 DATE, 금액 정수 만원, 면적 소수 2자리, 지역 코드 5자리 문자열
- **시계열 최적화**: (complex_id, deal_date)·(region_code, deal_date) 복합 인덱스, 월별 집계 테이블
- **권한 분리**: 개인정보는 users 에만 저장, 관리자 조회 API 에서 test_admin 마스킹, 탈퇴 시 CASCADE 삭제
- **TiDB 호환**: 모든 문자열 VARCHAR 길이 지정(인덱스 키 191자), JSON 컬럼, `pool_pre_ping`·`pool_recycle=300`, TLS 인증서 검증
- 대용량 이미지·분석 산출물·모델 가중치는 Object Storage 저장 원칙 (`property_images.url`), 저장소 커밋 금지(.gitignore)
