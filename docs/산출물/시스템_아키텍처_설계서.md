# 시스템 아키텍처 설계서

> 작성: 홍기흥 (Backend · Infra) · 기준 커밋: 초기 구축

## 1. 구성도

```
[사용자 브라우저]
   │  React SPA (Vite build)
   ├─ Netlify  aptpick.netlify.app ── VITE_USE_MOCK=true → 브라우저 Mock(snapshot.json, 가상 샘플)
   ├─ Render Static  aptpick.onrender.com ──┐
   └─ AWS EC2  aptpick.duckdns.org ─ Nginx(HTTPS, Let's Encrypt) ─┬─ /      → web 컨테이너(nginx:80)
                                                                  └─ /api, /ws → api 컨테이너(uvicorn:8000)
                                              │
                         Render Web  aptpick-api.onrender.com (FastAPI · Uvicorn)
                                              │ SQLAlchemy + PyMySQL (TLS, certifi CA)
                                        TiDB Cloud  database=aptpick
   외부: 국토교통부 실거래 OpenAPI(data.go.kr) · Kakao Local · Google Gemini · OAuth(Google/Naver/Kakao) · OpenStreetMap/Kakao Map
```

## 2. 백엔드 계층 (`backend/app`)
| 계층 | 위치 | 역할 |
|---|---|---|
| core | `core/config.py`, `core/security.py` | 단일 `.env` 로드, DB URL 조립(TiDB→SQLite 대체), JWT·PBKDF2 |
| database | `database/__init__.py` | 엔진·세션, TiDB TLS(VERIFY_IDENTITY), `CREATE DATABASE IF NOT EXISTS aptpick` |
| models | `models/__init__.py` | 24개 테이블 (DB 설계서 참고) |
| schemas | `schemas/__init__.py` | Pydantic 입력 검증 |
| middleware | `middleware/__init__.py` | test_admin 쓰기 403, IP 기준 Rate Limit, 보안 헤더 |
| dependencies | `dependencies/__init__.py` | 현재 사용자·관리자 조회/쓰기 권한·마스킹 판단 |
| repositories | `repositories/apartments.py` | 검색 쿼리(필터·정렬·페이지) |
| services | `services/*` | seed, stats(pandas), features(입지), prediction(ML), recommendation, anomaly, report(Gemini), collector(국토부), realtime(WS 허브), oauth, common(감사·마스킹·알림) |
| routers | `routers/*` | auth · apartments · market · ai · me · reports · admin · ws |

- 기동 시: 테이블 생성 → 마스터/테스트 계정 → (데이터 없을 때) 가상 샘플 적재 → 지역 통계 집계 → 백그라운드 모델 학습·초기 리포트
- 모델 학습 중 요청은 대기하지 않고 “학습 중” 응답 (Render 무료 CPU 대응)

## 3. 프런트엔드
- React Router 7(지연 로딩), TanStack Query(경로+파라미터 queryKey), Axios(토큰 인터셉터·오류 정규화)
- `VITE_USE_MOCK=true` 빌드에서만 Axios adapter 를 Mock 서버로 교체 (운영 번들에서는 상수 치환으로 제거)
- 지도 엔진 추상화: Leaflet+OSM 기본 / Kakao Maps SDK(`VITE_MAP_PROVIDER=kakao`)

## 4. 보안
- JWT(HS256) + 역할 클레임, 관리자 권한은 백엔드 의존성(`require_admin_view/write`)과 미들웨어 이중 검증
- 실제 관리자는 `ADMIN_SECRET_KEY` 상수 시간 비교, 감사 로그(행위자·IP·변경 내용)
- CORS 허용 도메인 제한, Rate Limit(전역 240/분, 로그인 20/분 등), SQLAlchemy 바인딩으로 SQL Injection 방지
- 개인정보 마스킹(테스트 관리자), 비밀값은 `.env`/플랫폼 환경 변수·GitHub Secrets 로만 관리

## 5. CI/CD
| 워크플로 | 트리거(Path Filter) | 내용 |
|---|---|---|
| `deploy-backend.yml` | `backend/**`, `ai/**` | pytest(백엔드·AI) + Docker 빌드 → 통과 시 Render(`checksPass`) 자동 배포 / `health` 잡: 6시간 주기·수동 |
| `deploy-frontend.yml` | `frontend/**`, `netlify.toml` | 실제 API·Mock 두 모드 빌드 → Render Static·Netlify 자동 배포 / `health` 잡 |
| `deploy-aws.yml` | `backend/**`, `frontend/**`, `deploy/**`, `docker-compose.yml` | 테스트·compose 검증 → SSH rsync → `remote-deploy.sh`(릴리스 전환·빌드·Health Check·롤백) → 공개 Health Check |

- Render/Netlify Deploy Hook 미사용. push 워크플로에서 Render 배포 완료를 기다리면 `checksPass` 가 모든 체크 완료를 기다리므로 교착 → 배포 후 상태 확인은 별도 `health` 잡으로 분리
- AWS Secrets 미설정 시 배포 단계는 건너뜀(성공 처리)
